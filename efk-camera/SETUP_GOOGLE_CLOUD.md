## ステップ1：プロジェクトを作る

1. https://console.cloud.google.com/projectcreate を開く
2. **プロジェクト名**：`EFK CAMERA`
3. 「作成」

作成後、画面上部のプロジェクト選択が `EFK CAMERA` になっていることを確認してください。
**以降のすべての操作で、ここが `EFK CAMERA` になっているか毎回確認してください。**

## ステップ2：YouTube Data API v3 を有効にする

1. https://console.cloud.google.com/apis/library/youtube.googleapis.com を開く
2. プロジェクトが `EFK CAMERA` になっているか確認
3. 「有効にする」をクリック

## ステップ3：OAuth 同意画面を作る

1. 左メニュー「APIとサービス」→「OAuth同意画面」
2. **User Type**：`外部` を選んで「作成」
3. 入力する項目

   | 項目 | 入力する値 |
   |---|---|
   | アプリ名 | `EFK CAMERA` |
   | ユーザーサポートメール | `emfrentekumamoto@gmail.com` |
   | デベロッパーの連絡先情報 | `emfrentekumamoto@gmail.com` |

   ※ ロゴやホームページは空のままで構いません
4. 「保存して次へ」

---

## ステップ4：スコープを追加する

1. 「スコープを追加または削除」をクリック
2. 右上のフィルタに `youtube` と入力
3. 次の**2つ**にチェックを入れる

   | スコープ | 用途 |
   |---|---|
   | `.../auth/youtube.upload` | 動画のアップロード |
   | `.../auth/youtube.readonly` | **アップロード成功の確認**（元動画を削除してよいかの判断に必須） |

4. 「更新」→「保存して次へ」

> `youtube.readonly` を外すと、
> **「本当にアップロードできたか」を確認できなくなり、自動削除が一切動かなくなります。**
> 必ず両方入れてください。

## ステップ6：Android の OAuth クライアントを作る（★ここが要）

必要なのは **SHA-1 をひとつ**だけです。

`keystore.properties` を置いてビルドすると、debug も release も同じ鍵で署名されるように
してあるので、登録する SHA-1 は1つで済みます。

```bash
cd efk-camera
./gradlew signingReport
```

出力の `Variant: release` の `SHA1:` の値を控えてください。

> `keystore.properties` を置かずにビルドした場合だけ、debug が Android Studio の
> 自動生成鍵になり SHA-1 が変わります。その場合は `Variant: debug` の SHA-1 も
> 同じ手順でもう1件登録してください。

Google Cloud で登録します。

1. 左メニュー「APIとサービス」→「認証情報」
2. 「+ 認証情報を作成」→「OAuth クライアント ID」
3. 入力する項目

   | 項目 | 入力する値 |
   |---|---|
   | アプリケーションの種類 | `Android` |
   | 名前 | `EFK CAMERA` |
   | パッケージ名 | `jp.efk.camera` |
   | SHA-1 証明書フィンガープリント | 上で控えた値 |

4. 「作成」→「OK」

> **なぜ SHA-1 が要るのか**
> Android の OAuth は「パッケージ名 + 署名の SHA-1」で本人確認します。
> 署名鍵が変わると SHA-1 も変わり、認証だけが失敗するようになります。

> **クライアントシークレットは発行されません。** Android 型はそういう仕様です。
> つまり **アプリにもリポジトリにも、秘密にすべき文字列は一切入りません。**

## ステップ8：テストアップロードをする

1. 操作端末のブラウザから接続
2. 試合名に `接続テスト` と入力

6. KYV47 の空き容量が元に戻っていることを確認（元動画が自動削除された）

ここまで通れば設定は完了です。

## ステップ9：公開設定について（読むだけ・作業なし）

テストアップロードした動画は、おそらく **「非公開（private）」** になっています。

これは不具合ではなく、YouTube Data API の仕様です。

> Google の監査を受けていない API プロジェクトからアップロードされた動画は、
> `unlisted`（限定公開）を指定しても強制的に `private` になる。

アプリはこれを検知して、操作画面にこう出します。

```
✓ アップロード完了
  ⚠ 現在API制限により非公開でアップロードされています
```

### どうするか

| 選択肢 | 内容 |
|---|---|
| **A. そのまま運用（おすすめ）** | アップロードは成功しているので、YouTube Studio で必要な動画だけ「限定公開」に変更する |
| B. 監査を申請する | Google Cloud の OAuth 同意画面から申請。通れば自動で限定公開になるが、審査に数週間かかる |

**まずは A で始めることをおすすめします。** 運用してみて手間だと感じたら B に進みましょう。

## クォータについて（覚えておいてください）

YouTube Data API は 1日あたりの利用量に上限があります。

```
既定の上限 10,000 / アップロード1本 = 1,600
→ 1日あたり およそ 6本まで
```

大会日に7試合以上を1日で上げると上限に当たります。その場合は：

- 翌日に分けてアップロードする（アプリは自動で再試行します）
- または Google Cloud の「APIとサービス → YouTube Data API v3 → 割り当て」から増加申請

アプリは上限に当たっても **元動画を消しません**。翌日以降に自動で再試行します。

## 困ったときの確認先

| 症状 | 見るところ |
|---|---|
| アカウント選択後に認証が通らない | ステップ6の SHA-1。`./gradlew signingReport` の値と一致しているか。インストールした APK と同じ鍵で署名されたものか |
| `403 accessNotConfigured` | ステップ2。API が有効になっているか |
| `403 insufficientPermissions` | ステップ4。スコープが2つとも入っているか |
| 同意画面で弾かれる | ステップ5。テストユーザーに入っているか |
| アップロードが `quotaExceeded` | クォータ上限。翌日に自動で再試行されます |
